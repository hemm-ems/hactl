row each, decided **before** code builds on them (see workspace `AGENTS.md`,
"Spec before code"). A decided row records the decision and the law/test it
materialized into; nothing here carries a count or a status narrative.

| D-14 | Config writes and formatting — a single-entry write re-serialized the whole file. Is byte preservation a goal at all, and if it is, where does the fix stop? (live-fire 2026-07-30 P1 #4: one confirmed automation write reformatted ~34 unrelated real automations; semantically lossless, so every value-level test stayed green) | DECIDED 2026-07-30: **byte preservation is a contract, not a nicety** — a write that changes one entry changes one entry's lines and leaves every other byte alone, because a config directory is a git repo and a diff nobody asked for is the whole cost. Two consequences settle the rest. (a) **The check is on bytes, never on parsed values**: the defect *was* semantically lossless, so a parse-and-compare gate would have certified it clean — which is exactly what happened for months. (b) **The fallback is loud**: a file the splice cannot carry (an anchor defined in the replaced entry, a flow-style top level) is re-serialized whole and the response says `reformatted: true`, absent otherwise — logging it instead would repeat the `ServiceResult` mistake of knowing the reason and telling nobody. **Scope, recorded rather than implied**: the fix is *entry*-granular, so it covers `POST/PUT/DELETE /v1/config/{automation,script,template,helper}` and nothing else. `POST /v1/ref/replace` is *leaf*-granular (scalars at arbitrary depth across a whole `!include` graph) and keeps re-serializing — so `ent rename` still reformats — hactl-companion #88. `auto apply`/`auto rollback` post to HA's own `/api/config/automation/config/<id>`, which re-dumps the file itself; unfixable in the companion and rerouted from hactl instead — #128. Both are enumerated with a written reason in the companion's `FILE_WRITES` table, not left as gaps. | hactl-companion `companion/surgical.py` (line splice + a re-parse-and-compare verification that falls back to the old whole-file dump on any disagreement, so the new path can change formatting and never content); companion `INVARIANTS.md` C-13 + `test_single_entry_write_leaves_every_other_byte_alone` (sweeps every write route, with an anti-vacuity guard that re-runs the old writer on the same input) + `test_every_file_write_declares_a_formatting_stance` (canary: `surgical` or a `whole_file_reason`); `tests/test_surgical.py`; oracle `TestSurgicalWrites::test_home_assistants_own_config_api_reserializes_the_whole_file` (HA's behaviour asserted, so the boundary claim fails instead of becoming folklore); owed here: `make sync-spec` + surfacing `reformatted` |
