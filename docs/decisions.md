# Decisions

Choices a test cannot express: canonical identifiers, defaults, naming. One
row each, decided **before** code builds on them (see workspace `AGENTS.md`,
"Spec before code"). A decided row records the decision and the law/test it
materialized into; nothing here carries a count or a status narrative.

| D-7 | `ref validate --exit-code` silently skips a dashboard whose config fetch fails — the unfixed half of P1-8, and D-6's vacuous-gate shape on the one command whose whole job is to certify a tree. | DECIDED 2026-07-28: loud partial, gated on who reads the answer. Search commands (`ref scan`, `dash grep`) report what they could not read and still answer. **Extended 2026-07-28, same day, after a verification pass: the rule is per _source_, not per dashboard.** Stating it in terms of dashboards is how it shipped one source short — `ref validate` reads four (entity registry, live states, config files, every dashboard) and the registry degraded the live set at `slog.Warn` and reached no gate, so the fix for a silent dashboard left a silent registry one function beneath it. Live states keep the stricter posture — refuse in every mode — because the registry alone omits every state-only entity and is not a usable live set. **Known limit, recorded rather than implied:** the "config files" source is one wire call over N files, and the companion silently skips a file it cannot read (missing `!include` target, unreadable, circular). hactl cannot see those skips until it consumes the `skipped` array (hactl-companion #81) after a companion release, so this row does not yet claim the config half is gated file-by-file. | one `walkDashboardConfigs` shared by `ref validate`, `ref replace`, `ref scan` and `dash grep` (three walks collapsed into one, so the class has one site rather than a gate over two) + one `validateScanGateError` over three sources plus an unconditional refusal for live states, all four carried in `validateScope`; `TestRunRefValidate_UnscannableDashboardRefusesUnlessAllowPartial`, `TestRunRefValidate_UnreadableRegistryRefusesUnlessAllowPartial`, `TestRunRefValidate_UnreadableConfigHalfRefusesUnlessAllowPartial`, `TestRunRefValidate_AutoGeneratedDefaultIsNotAPartialSweep`, `TestRunRefScan_UnscannableDashboardStillAnswers`, `TestRunRefValidate_RegistryOnlyRefusedWithoutAllowPartial`; laws: H-10 |
| D-8 | `auto ls`/`script ls` die on an entity they do not list — a foreign `current: -1.7525` fails a decode of the whole `/api/states` into their own domain-typed struct. Is the pole "attributes are schema-tolerant" or "filter before decode"? | DECIDED 2026-07-29: the **ordering** rule (H-21). A command may keep a typed attribute schema for the entities it actually renders; what it may not do is apply that schema to entities it discards. Widening `Current` to a tolerant numeric type is explicitly **not** the fix — it addresses one key, leaves the next collision to production, and would make the reproduction pass for the wrong reason. The oracle settled the companion question: HA computes `current` as `Script.runs` → `return len(self._runs)`, integral by construction, so the field is correct for every entity the listing renders. **The collision ships in stock HA, not in exotic integrations** — `max` is integral on `automation.*`/`script.*` and fractional on `number.*` in the same response, so `automationAttributes` is one `Max int` field away from failing on a default install. The current pole was held by luck, not design. Marker 1 ("which entity emitted `-1.7525`") was **retired by scope, not probed**: the reporting instance is a third party's and unreachable, and a different answer would have produced neither different code nor a different test — it would have produced a *narrower* fixture than acceptance criterion 1 already demands. That discriminator is now ritual, in the workspace `AGENTS.md` "Spec before code" item 1. | `internal/cmd/states.go` (`statesEnvelope` + `fetchDomainStates` + `decodeStateAttributes`); `TestAutoLsIgnoresAttributesOfEntitiesItDiscards`, `TestScriptLsIgnoresAttributesOfEntitiesItDiscards`, `TestColliderCoversEachStructsOwnKeys`, `TestStatesWithoutEntityIDStillPoisonsTheListing`, `TestAutoLsIgnoresAForeignEntitysAttributeTypes`, `TestScriptLsIgnoresAForeignEntitysAttributeTypes`, `TestEntListingsStillSeeTheColliderIsTheControl`; oracles `TestOracleStatesCarriesOneKeyAtTwoJSONTypes`, `TestOracleAutomationScriptCurrentIsIntegral`, `TestOracleStatesSixKeyDomainCensus`; closure gate `TestDomainDecodeSurfaceIsClosed` over `dev/surfaces/domaindecode.manifest`; law: H-21 |
| D-9 | A defect reported from an instance nobody here can reach cost a source-reading session to diagnose, because the error named hactl's Go type and not the entity. What diagnostic mechanism answers that class — a `--debug` flag producing a dump? | DECIDED 2026-07-29: **no `--debug` flag.** It needs the user to know to re-run, needs the failure to reproduce, and the failing run already held the payload. Three layers instead, and only the first ships now. **Layer 0 — the error names the record** (`entity <id>: attributes.<key>: …`): in scope, because it *manufactures oracles* — every future report of this class arrives with its own diagnosis inside it. Note it needs more than a per-entity loop: the message is reconstructed from `*json.UnmarshalTypeError`'s `Field`/`Value`/`Type`, since decoding per entity still yields encoding/json's Go-type-centric phrasing. **Layer 2 — `hactl doctor`, scoped to a redacted wire shape census**: deferred to its own item; capture shapes, not values, because `/api/states` is a description of someone's home and a raw dump attached to a public issue is a privacy incident — and a shape record is mechanically convertible into a fixture, closing the report → oracle → red test → fix loop. **Layer 1 — automatic capture on error: dropped**, not deferred; once layers 0 and 2 exist its only remaining value is a transient unreproducible failure, at the highest machinery cost of the three. | `attributeDecodeDetail` in `internal/cmd/states.go` + `TestStatesDecodeErrorNamesTheEntityAndKey`; layer 2 unbuilt by design; law: H-21 |
