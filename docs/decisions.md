# Decisions

Choices a test cannot express: canonical identifiers, defaults, naming. One
row each, decided **before** code builds on them (see workspace `AGENTS.md`,
"Spec before code"). A decided row records the decision and the law/test it
materialized into; nothing here carries a count or a status narrative.

| D-7 | `ref validate --exit-code` silently skips a dashboard whose config fetch fails — the unfixed half of P1-8, and D-6's vacuous-gate shape on the one command whose whole job is to certify a tree. | DECIDED 2026-07-28: loud partial, gated on who reads the answer. A dashboard that could not be scanned refuses the run under `--exit-code` **or** `--json` unless `--allow-partial` — a warning is invisible to a machine consumer, and H-10 makes `--json` a machine contract, so an unread dashboard must not reach one as a clean verdict. Plain text states the partial scope in the report body, never only in a log. An auto-generated default is a complete zero, not a partial. Search commands (`ref scan`, `dash grep`) report what they could not read and still answer. **Extended 2026-07-28, same day, after a verification pass: the rule is per _source_, not per dashboard.** Stating it in terms of dashboards is how it shipped one source short — `ref validate` reads four (entity registry, live states, config files, every dashboard) and the registry degraded the live set at `slog.Warn` and reached no gate, so the fix for a silent dashboard left a silent registry one function beneath it. All four are now recorded in one `validateScope` and reported by one function; three of them (registry, config files, dashboards) then share `validateScanGateError`, while live states refuse unconditionally from their own branch in `liveEntitySet` — a different message for a different consequence, not a posture flag on the shared one. Both directions are gated: an unread config file or dashboard hides references (false clean bill), a degraded live set reports existing entities as dangling (false alarm). Live states keep the stricter posture — refuse in every mode — because the registry alone omits every state-only entity and is not a usable live set. **Known limit, recorded rather than implied:** the "config files" source is one wire call over N files, and the companion silently skips a file it cannot read (missing `!include` target, unreadable, circular). hactl cannot see those skips until it consumes the `skipped` array (hactl-companion #81) after a companion release, so this row does not yet claim the config half is gated file-by-file. | one `walkDashboardConfigs` shared by `ref validate`, `ref replace`, `ref scan` and `dash grep` (three walks collapsed into one, so the class has one site rather than a gate over two) + one `validateScanGateError` over three sources plus an unconditional refusal for live states, all four carried in `validateScope`; `TestRunRefValidate_UnscannableDashboardRefusesUnlessAllowPartial`, `TestRunRefValidate_UnreadableRegistryRefusesUnlessAllowPartial`, `TestRunRefValidate_UnreadableConfigHalfRefusesUnlessAllowPartial`, `TestRunRefValidate_AutoGeneratedDefaultIsNotAPartialSweep`, `TestRunRefScan_UnscannableDashboardStillAnswers`, `TestRunRefValidate_RegistryOnlyRefusedWithoutAllowPartial`; laws: H-10 |
